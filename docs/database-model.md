# Modelo proposto — PostgreSQL

Documentação apenas; nenhuma tabela criada. PK de cada tabela: `id uuid`. Todas incluem `created_at timestamptz NOT NULL` e `updated_at timestamptz NOT NULL`, preenchidas pelo backend. Instantes UTC; datas de relatório no fuso da conta. Contagens `bigint CHECK >= 0`; NULL para indisponível, diferente de zero. Taxas calculadas em consultas.

## Antes das migrações

- Alcance/usuários únicos de 30 dias exigem agregados da fonte, não soma diária. Se persistidos, criar agregados com início/fim e chave única da consulta.
- GA4 Data API traz relatórios agregados; não presumir eventos individuais para website_events. Definir coleta própria/exportação ou substituir por métricas de eventos agregadas por dia/página/campanha.
- Palavras-chave do Business Profile podem ser mensais e ter limiares; modelar tabela separada após validar disponibilidade. Não misturar com números diários.
- Criar índices de FKs/datas conforme consultas; deletar contas/negócios com restrição e política explícita de retenção.
- Isolar negócios no backend. Se Supabase, definir RLS antes de acesso público. Segredos em armazenamento seguro exclusivo do servidor, nunca frontend ou tabelas de analytics.
